# 研判与评测体系

这套工作流的判断标准和打分标准，从初五的 [Chuwu-PR-OS](https://github.com/chuwu57/Chuwu-PR-OS)（PROS 05，MIT）改写而来，许可见同目录 `CHUWU-PR-OS-LICENSE.txt`。改写的地方：原框架是给人或 Agent 读材料做研判的，这里拆成三层，让 n8n 每次定时跑都能落成可核对的字段和分数。

| 层 | 做什么 | 谁来做 | 来自 Chuwu 的哪部分 |
| --- | --- | --- | --- |
| 编码 | 每条笔记 / 评论打标签 | DeepSeek Flash | 舆情等级三维度、危机情绪高压线、用户动员六级链路、VOC 编码（原话与证据性质分开）、舆论事件格式判断 |
| 研判 | 汇总成研判和交接包 | 指标由代码算，结论由 DeepSeek Flash 写 | `hot-public-opinion-analysis` 的判断顺序和输出结构、平台传播与信任判断（可见性 ≠ 态度）、拟态环境还原、PR Skill 八字段交接包 |
| 评测 | 给研判打分、抽检编码 | 规则检查由代码做，打分和抽检由 DeepSeek V4 Pro 做 | 质量红线、PR 输出质量评估（舆情任务权重）、质检器硬停止 |

## 一、编码字段

每条记录（笔记正文或评论）一行，字段固定，模型只能从枚举里选：

| 字段 | 取值 | 依据 |
| --- | --- | --- |
| target 指向 | 本机构 / 同名或其他机构 / 泛讨论 / 无法判断 | 不把外部事件硬拉到本业务；同名机构多，先分清是不是在说我们。判定规则写在「配置」的 `target_rule`，编码和抽检复核共用。学思堂：能落到无锡的才算本机构；特斯拉：排除物理学家、磁感应强度单位和只聊别家车的比较帖 |
| sentiment 情感 | 正面 / 中性 / 负面 / 混合 | |
| tone 语气 | 推荐 / 询问 / 陈述 / 质疑 / 抱怨 / 愤怒 / 嘲讽 / 避雷警告 / 玩梗 | 语气和情感分开，同样是负面，抱怨和避雷警告的传播力不一样 |
| intensity 情绪烈度 | 0–3 | 三维度的情感维度 |
| topics 涉及内容 | 随行业变，写在「配置」`industry.topics`。汽车：产品质量与故障 / 安全事故 / 辅助驾驶 / 车机与软件 / 续航与充电 / 价格与优惠 / 销售与交付 / 售后与维修 / 保险与残值 / 设计与配置 / 品牌与创始人言论 / 员工与招聘 / 其他；教培：教学效果 / 师资 / 收费价格 / 退费 / 服务态度 / 校区环境与安全 / 营销宣传 / 员工与招聘 / 其他 | 三维度的内容维度 |
| high_voltage 高压线 | 随行业变，写在 `industry.high_voltage`。汽车：安全 / 质量缺陷 / 消费公平 / 被轻视感 / 虚假宣传 / 隐私 / 民族情绪 / 劳动者；教培：未成年人 / 安全 / 消费公平 / 被轻视感 / 虚假宣传 / 隐私 / 劳动者 | 危机情绪高压线地图，按行业改写 |
| mobilization 动员级别 | 0–6 | 用户动员六级链路：1 私下反馈、2 公开喊话、3 组织化协同、4 晒证据做素材、5 行动施压（退订退费、劝退、避雷）、6 第三方（12315、市场监管或教育局、车质网等投诉平台、媒体、律师）；1 / 5 / 6 级的行业说法写在 `industry.mobilization` |
| collective_recall 集体经验召回 | 是 / 否 | 「我也是」「我家也遇到过」，低传播高共鸣不能低估 |
| evidence 证据性质 | 亲历自述 / 转述 / 询问 / 无法判断 | VOC 编码：本人自述、他人转述分开标，「他说退不了费」仍是自述 |
| quote 原话 | 原文中最能代表判断的一段 | 只能摘原文，不能改写 |
| format 格式 | 笔记：亲历分享 / 截图爆料 / 测评对比 / 资讯转述 / 玩梗二创 / 挂话题蹭热 / 广告营销 / 其他；评论一律「评论」。视频还是图文由代码从笔记详情里取 | 舆论事件格式判断：同一件事，截图爆料、长文、玩梗、只挂话题的传播方式和回应方式都不一样 |
| compare_with 对比对象 | 在拿本机构和别家比时，写被比的品牌、产品或事件；没有对比为空 | 不把外部事件硬拉到本业务 |
| compare_side 谁占上风 | 本机构占上风 / 本机构落下风 / 不分高下 / 无对比 | 占上风的对比不是本机构的风险，要看的是会不会被卷进阵营争吵 |

高压线只标本机构自己碰到的：拿别家的事故、缺陷对比本机构，或者嘲讽别家的，高压线空着，别家写进 compare_with。「配置」`context_notes` 放人工核实过的外部背景（特斯拉版：「刹车踩断」说的是懂车帝测出的江淮尊界刹车踏板断裂，不是特斯拉），编码、研判、抽检的提示词都会带上，和模型常识冲突时以它为准。编码字段改了就把「配置」`coding_version` 加 1，缓存里版本更低的记录下次重新编码。

编码过的记录按 ID 缓存，下次定时跑只编码新增的评论。

**指向兜底（代码）**：评论或回复要算本机构，所在笔记或上层评论得是本机构，或者原文里有「配置」`target_clues` 里的线索（学思堂版：学思堂、无锡、无锡的区名；特斯拉版：特斯拉、Tesla、Model、毛豆、马斯克、FSD、超充……）；否则降为无法判断。加这条是因为实跑时，模型把《无锡某学开始收费了》（判为别家）下面 7 条没有任何线索的评论判成了本机构，研判据此写出了「家长端催续费」。

## 二、研判指标（代码计算，不经模型）

只统计 `target = 本机构`、且落在研判窗口内的记录。研判窗口默认过去 24 小时，「配置」`window_days` 可改成 7 或 30；笔记按发布时间、评论按发表时间算，老帖下的新评论也算。另算两组参照：和前一个同样长的窗口比（条数、负面、碰高压线的条数，只看方向，因为越早的评论越可能没被抓到）；窗口外的存量（条数、负面、话题）只当背景。每个数字都带分母：片段数、笔记数、独立用户数分开写。

- **传播维度**：窗口内有动静的相关笔记数、其中窗口内新发的、作者数、互动总量（赞 + 藏 + 评 + 转，是累计值）、和窗口起点那次快照比的互动增量（快照不够一个窗口时为空）、和上次快照比的互动增量。只覆盖小红书一个平台，跨平台扩散一律记「未覆盖」。
- **情感维度**：负面占比、烈度 ≥2 的条数、集体经验召回条数。
- **内容维度**：高压线命中次数和类型。`industry.severe_high_voltage`（汽车：安全、民族情绪）一碰就拉到高；`escalate_with_mobilization`（汽车：消费公平、质量缺陷）和 5 级以上动员同时出现才拉到高。
- **动员**：最高动员级别、5 级以上条数。
- **公众实际看到的版本**：每个关键词搜索结果的前 5 篇（排名、格式、指向、情感、是不是对比）、窗口内互动最高的 3 篇，以及它们下面点赞最高的 3 条评论；相关笔记的格式分布；对比记录数、被比对象、谁占上风。排名、互动量、高赞只说明被看见的程度，不说明有多少人持这个态度。
- **官方号评论区**：「配置」`official_accounts` 填了 user_id 的官方号，抓它最近 `official_notes_per_account` 篇笔记的评论，算窗口内的条数、负面、公开喊话及以上的条数。没填就记「未覆盖」；搜索结果里出现同名作者时，附一会列出它的 user_id。

三个维度各自分「低 / 中 / 高」（阈值写在工作流的「配置」节点里，可以改），**风险量级取三者最高，不取平均**（原框架：任一维度爆表都要警惕）。

## 三、研判输出

结构照 `hot-public-opinion-analysis`：

- **判断基准**：决策主体（配置里的 `decision_subject`，学思堂版是市场部，特斯拉版是特斯拉中国品牌公关部）、时间锚点、证据缺口。
- **零、过去 24 小时（或 7 天 / 30 天）的变化**：窗口里新增了什么，和前一个窗口比多了还是少了；只能引用窗口内的记录。
- **公众实际看到的版本**：搜这些关键词先看到哪几篇、是什么格式、高赞评论在说什么，这个版本由哪些材料拼成、和实际情况差在哪。
- **一、是否已经形成舆情**：已形成舆情 / 舆情前夜 / 尚未形成舆情 / 传播证据不足，暂不可分档。
- **二、舆情实质**：冒犯了谁、激活了哪种情绪、被贴了什么标签、为什么是现在。
- **三、走势**：潜伏期 / 激化期 / 爆发期 / 反转期 / 降温期 / 阶段暂不可判断；升级条件、降温条件用条件句。
- **四、对业务的参考意义**：会不会被类比或误伤、要自查什么、下一步（观察即可 / 内部自查 / 转公关决策）。
- **交接包**：下一步不是「观察即可」时，照 PR Skill 最小交接协议写八个字段：决策主体、时间锚点、已确认事实、证据 / 反证 / 缺口（三样分开，没有反证写「未取得反证」）、最大不确定性、资产与业务影响、可选动作及代价、需要下游决定或产出的事项。交给后面决定要不要回应、谁回应的人，不重复前面的论证。

写实质之前先找最有力的替代解释：负面是不是其实在说别家、是不是玩梗、是不是存量。每条判断都要挂记录 ID。

## 四、评测

### 1. 规则检查（代码，硬红线）

R0 是 2026-10-16 加的：电脑睡眠后小红书 MCP 变慢，两个关键词搜索超时返回 0 条，样本只剩三分之一，研判和打分却照样拿了 A。评测只管写得好不好，管不到数据采没采全，所以把采集完整性也列进规则。

| 编号 | 检查 | 依据 | 不过的后果 |
| --- | --- | --- | --- |
| R0 | 每个关键词都搜到了东西 | 先做事实核验：访问失败不等于没有舆情 | 封顶 B |
| R1 | 结构完整 | 输出结构 | 封顶 C |
| R2 | 分档在四个取值里 | 判断顺序 1 | 封顶 C |
| R3 | 快照没跨满一个研判窗口时（24 小时窗口要有 24 小时前的快照），阶段只能写「阶段暂不可判断」 | 没有连续传播证据时不判断阶段 | 封顶 C |
| R3b | 快照跨满窗口时，阶段在六个取值里 | 判断顺序 3 | 封顶 C |
| R4 | 引用的记录 ID 都真实存在，且至少引用一条（写短、或把评论的 c_ 写成笔记的 n_，能唯一对上就补全，按 R4b 扣分） | 不编造来源 | 封顶 C |
| R4b | 引用写全 ID | 方便核对 | 扣 3 分 |
| R5 | 报告里出现的百分比都能在指标里找到 | 不编造数据 | 封顶 C |
| R6 | 只覆盖一个平台时，证据缺口要写明其他平台未覆盖 | 传播证据不足 ≠ 尚未形成 | 封顶 B |
| R7 | 同名或无法判断的记录超过三成时，要在判断基准里交代 | 不把外部事件硬拉到本业务 | 封顶 B |
| R8 | 不出现「加强沟通」「高度关注」这类空话 | 质量红线 | 扣 3 分 |
| R9 | 不出现「广大家长」「公众普遍」这类外推 | 评论区不等于整体公众 | 扣 3 分 |
| R10 | 不替法务定责（「违法」「构成欺诈」） | 质量红线 | 扣 3 分 |
| R11 | 写了决策主体和带日期的时间锚点 | 判断基准 | 封顶 B |
| R12 | 「窗口变化」一段只引用窗口内的记录 | 不把存量写成近期新增 | 封顶 B |
| R6b | 官方号评论区没覆盖时，证据缺口要写明 | 半公开喊话主要发生在官方号评论区 | 封顶 B |
| R13 | 不出现「形成共识」「公众认为」「普遍认为」这类把可见性写成态度的说法 | 声量只能写成「可见性上升」 | 扣 3 分 |
| R14 | 写了「公众实际看到的版本」并引用记录 | 拟态环境还原 | 封顶 B |
| R15 | 下一步不是「观察即可」时，交接包八个字段齐全 | PR Skill 最小交接协议 | 封顶 B |

R8、R9、R10、R13 这几条措辞规则只查研判自己写的话，「」里引用的网友原话不算。

### 2. 模型打分（DeepSeek V4 Pro）

七个维度照「PR 输出质量评估」，按原框架「危机、舆情、口径审查」一行调高事实证据、公共语境、风险控制的权重：

| 维度 | 原权重 | 本工作流 |
| --- | --- | --- |
| 问题识别 | 15 | 10 |
| 事实和证据 | 15 | 20 |
| 公共语境 | 15 | 20 |
| 品牌和业务匹配 | 15 | 10 |
| 策略可执行性 | 15 | 15 |
| 表达质量 | 15 | 10 |
| 风险控制 | 10 | 15 |

等级：A 85–100 可直接用于内部讨论；B 70–84 可用但要人工校准；C 60–69 只能当素材；D 60 以下不合格。

最终等级 = 模型等级和规则检查封顶里**更低的那个**。低于 B 时报告顶上加原框架的提示：「这份结果只能作为讨论素材，不建议直接使用。请先补充事实、证据或组织动作，再生成发布版本。」

### 3. 编码抽检

每次从已编码记录里抽 12 条（负面、高压线、动员 ≥4 的优先），只给 Pro 看原文，让它独立重新编码 target、sentiment、high_voltage，代码算一致率。一致率低于 70% 时报告顶上标「编码可靠性不足」，不一致的记录列进附录等人工复核。

两个模型的一致不等于对，只能发现明显的错标。真正的准确率要靠人工标注的金标集：`eval/golden_template.csv` 填好后跑 `eval/score_golden.py`。
