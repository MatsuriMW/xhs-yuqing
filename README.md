# 小红书舆情研判

一个 n8n 工作流：定时在小红书搜品牌关键词，抓笔记和评论区，交给 DeepSeek 逐条编码，由代码算指标、模型写研判，最后用一组代码规则和另一个模型给研判打分。研判写完还留一道人工复核，复核出的误判写回配置和编码规则，下一轮自动生效。

示例：[特斯拉 Roadster 发布后 24 小时的研判](https://matsuri.site/demo/xhs-yuqing/)（2026-10-16 的一次运行，含人工复核前后的对照）；四次运行的报告、模型直出和编码表在 [examples/tesla-2026-10](examples/tesla-2026-10/)。仓库里的「配置」追踪的就是特斯拉（关键词「特斯拉」「特斯拉 投诉」「Model Y」），换品牌只改配置。

**研判窗口默认是过去 24 小时**：三维度只统计窗口内的新内容（笔记按发布时间，评论按发表时间，老帖下面的新评论也算），窗口外的存量只当背景。想看长一点，把「配置」里的 `window_days` 改成 7 或 30。报告开头先写「过去 24 小时的变化」，并和前一个同样长的窗口比。

它做的几件事：

1. **定时跑、增量编码**：每天 9:00 / 18:00 自动跑；编码过的评论按 ID 缓存，下次只编码新增的；每次留一份互动快照，第二次起能算增量。
2. **先分清是不是在说这个品牌**：每条先判断指向，只有指向本品牌的才进统计。同名的机构、同名的人、只聊别家的比较帖都要排除（特斯拉要排除物理学家和磁感应强度单位）。
3. **研判，不只是情感比例**：逐条编码语气、烈度、话题、高压线、动员级别、集体经验召回；三维度指标由代码算，模型只负责写「是否形成舆情 / 实质 / 走势 / 业务参考」，每句挂原话出处。
4. **看公众实际看到的版本**：每篇笔记记下它在各关键词下的搜索排名和格式（亲历、截图爆料、玩梗、只挂话题……），每条记录标有没有在拿别家对比、谁占上风；报告多一段「公众实际看到的版本」，排名和高赞只算可见性，不算态度。配了官方号还会抓它最近几篇笔记的评论区。下一步不是「观察即可」时，附一份八字段交接包。
5. **评测**：19 条规则检查（R0–R15、R3b、R4b、R6b，R0 查采集有没有残缺，R12 查有没有把存量写成近期新增，R13 查有没有把可见性写成态度）+ V4 Pro 七维度打分 + 编码盲抽检，输出 A/B/C/D 等级，低于 B 时报告顶上写「只能作为讨论素材」。
6. **人工复核写回流程**：人工核实过的外部背景写进「配置」`context_notes`，编码、研判、抽检的提示词都会带上。例：特斯拉那一轮的「刹车踩断」说的是另一个品牌的刹车踏板断裂测试，复核后加了「对比对象 / 谁占上风」字段，别家的事故不再算成本品牌的安全风险。

完整标准见 [framework/研判与评测体系.md](framework/研判与评测体系.md)。

## 流程

```
定时触发 / 手动运行
  → 配置（品牌、关键词、行业设定、阈值、模型）
  → 逐个关键词 ⟲ 搜索笔记（小红书 MCP search_feeds）/ 官方号走 user_profile →  拆解笔记列表（去重、每词取前 8 篇）
  → 逐篇笔记 ⟲ 抓取详情和评论（get_feed_detail，每篇最多 30 条一级评论）→ 结构化（笔记 + 评论拍平成记录，用户 ID 只存哈希）
  → 读取状态 → 增量对比 → 有新记录吗
      ├ 是 → 切批 → 编码 DeepSeek（deepseek-flash）→ 合并编码
      └ 否 ───────────────────────────────────────→ 合并编码
  → 聚合研判指标（代码算三维度）→ 构造研判请求 → 研判 DeepSeek（deepseek-flash）
  → 规则检查 → 评测 DeepSeek Pro（deepseek-v4-pro：打分 + 盲重编码）→ 评级与报告 → 写入 data/
```

## 输出

`data/` 下：

- `latest.md`：最近一次的研判报告
- `runs/<日期_时间>_研判报告.md`、`_run.json`（全部记录、编码、指标、评测）、`_summary.json`（一行摘要，方便看趋势）
- `state.json`：编码缓存、互动快照、笔记首次出现时间

## 换一家公司

只改「配置」节点（`src/01_config.js`），然后重新 build、导入：

- `brand`、`brand_context`、`decision_subject`、`keywords`
- `target_rule`、`target_clues`：什么算本机构；评论要算本机构，上层得是本机构或原文里有这些线索之一
- `context_notes`：人工核实过的外部背景（比如某个梗其实在说别家），编码、研判、抽检都会读
- `official_accounts`：官方号的昵称、user_id、xsec_token；空着就不抓官方号评论区
- `coding_version`：编码字段改了就加 1，旧缓存会重新编码
- `industry`：行业名、受众（「家长」「车主」）、话题枚举、高压线和说明、哪些高压线一碰就拉高、动员 1 / 5 / 6 级的说法、规则 R9 的外推词。提示词里的 `{{占位符}}` 和统计代码都从这里取
- `thresholds`：大品牌的互动量比本地小机构高一两个数量级，阈值要跟着调

换公司前把 `data/` 里的东西挪进 `archive/<旧品牌>/`，否则会沿用旧品牌的编码缓存和快照。

## 运行

依赖：本机的 n8n（npx 装的 2.15.1）、社区节点 `n8n-nodes-mcp`、[xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp)（二进制放在 `~/xiaohongshu-mcp-darwin-arm64`，要先扫码登录）、n8n 里的 DeepSeek 凭据。

第一次用：在 n8n 里建好「MCP Client」和「DeepSeek」两个凭据，把它们的 id 和名字填进 `build.py` 开头的 `CRED_MCP`、`CRED_DEEPSEEK`，再 build、导入。`workflow.json` 是 build 出来的，不进仓库；`data/` 是运行结果（抓到的笔记、评论和编码缓存），也不进仓库。

```bash
./start.sh          # 起小红书 MCP 和 n8n，开着才会定时跑；工作流要在 n8n 界面里点 Active
./start.sh once     # 不开界面直接跑一次
```

n8n 2.x 默认只许读写 `~/.n8n-files`，`start.sh` 把 `N8N_RESTRICT_FILE_ACCESS_TO` 设成了本目录的 `data/`。直接 `npx n8n start` 的话写文件那步会失败。

改工作流：改 `src/` 里的 JS 和 `src/prompts/` 里的提示词，然后

```bash
python3 build.py && npx n8n import:workflow --input=workflow.json
```

小红书 MCP 掉登录时报告会显示「抓到笔记 0 篇」，重新扫码：调 MCP 的 `get_login_qrcode`，或跑 `~/xiaohongshu-login-darwin-arm64`。

## 评测的边界

- 小红书的时间筛选（「一天内」「最新」）带上就卡到 5 分钟超时，电脑醒着也一样，所以搜索用默认排序，窗口在代码里按时间戳筛。默认排序偏向热帖，冷门的新帖可能进不了前 8 篇；评论每篇只抓前 30 条热评，窗口内的新评论在热帖下可能被挤掉。
- 窗口互动增量要等快照跑满一个窗口才有（24 小时窗口要隔天的快照）；之前只有窗口内的条数。
- 规则检查只能抓到机械性的错：采集残缺、编造 ID、编造百分比、单次快照就断言阶段、空话。判断本身对不对靠模型打分和人工。
- 引用的 ID 是真的、但那条评论根本不是在说本机构，规则和打分都看不出来，要顺着结论回查原文。
- 同一批数据重跑，分档会在「舆情前夜」和「暂不可分档」之间摇摆，Judge 分数差十几分；单次分数只说明过没过红线，不能拿来比两次谁写得好。
- 模型开了 JSON 模式也偶尔输出坏 JSON，编码合并、规则检查、评级三处都用宽松解析兜底；修不好时照样出报告，标 D 并附原始输出。
- 编码抽检是两个 DeepSeek 模型互相对照，一致不等于判对。真正的准确率要人工标金标集：`eval/score_golden.py export` 导出待标注表，标完用 `score` 算准确率和 kappa。
- 只抓小红书一个平台，跨平台扩散一律记「未覆盖」，所以分档最多能到「舆情前夜」或「暂不可分档」。
